53efaab (Actions 38328892770, Slurm 23047, g1/g4, exit 139 after 8m30s)
stopped through the new segfault guard: prefill-2 crashed with the same
stack as Slurm 22740 and 22814 (getenv <- ncclSocketDefaultMagic <-
bootstrapRoot) although NCCL_NVLS_ENABLE=0 was already exported, so
07d0576 fixed only part of the race.

Root cause from the source of the image's commit c76f4a85: NCCL setup in
cpp/tensorrt_llm/common/opUtils.cpp and
cpp/tensorrt_llm/runtime/ncclCommunicator.cpp calls
  setenv("NCCL_RUNTIME_CONNECT", "0", 0)
  setenv("NCCL_GRAPH_REGISTER", "0", 0)
  setenv("NCCL_NVLS_ENABLE", "0", 0)
each time a communicator is created, while NCCL bootstrap threads of an
earlier communicator call getenv(). With overwrite=0 the call is a no-op
for a variable that already exists, but adding a missing one reallocates
environ under the concurrent reader. NCCL_RUNTIME_CONNECT and
NCCL_GRAPH_REGISTER were still missing. libtensorrt_llm.so in the image
contains exactly these three names next to the NVLS fallback message.

Fix: export all three with the values TensorRT-LLM itself sets (0), so
its setenv calls change nothing and NCCL behaviour is identical. The
NVLS warning box still prints (it comes from the multicast probe in
ipcNvlsMemory.cu) and is harmless. Nothing else changes from 53efaab.
