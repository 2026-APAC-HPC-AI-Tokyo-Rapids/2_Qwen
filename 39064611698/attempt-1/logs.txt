Candidate 1 of the Decode epilogue/dispatch series, measured alone on top
of the N_SWAP hoist (2d91b50, sm90-decode-swap-ab-hoist.patch). New file
patches/deep-gemm-bench/sm90-decode-swap-ab-l1-quant.patch, applied after
the hoist patch (name order).

Why: the instrumented timeline of the hoist run 39062255256 shows the FC1
(SwapAB L1) epilogue at about 21 us per CTA (3.5 us per block). After the
SwiGLU values are staged as FP32 [token][64] in shared memory, one thread
per token reads its 64 values (compiled to 16 LDS.128) for the amax, then
reads them again for the FP8 quantize and writes 32 two-byte pairs. The
row stride is 256 bytes, so the eight threads of every LDS.128 phase hit
the same four banks, and at most 64 of the 256 math threads are active.
The staging stores themselves were 4-way conflicted (the four token pairs
of a store map to the same eight banks).

What changes (Decode SwapAB path only; Prefill does not instantiate it):
- The FP32 staging column is XOR-swizzled by 8 * ((token / 2) % 4), so a
  warp's staging stores cover all 32 banks.
- Four threads per token (256 threads = 64 tokens = BLOCK_M, one pass):
  each loads four float4 of its token row, slot order rotated by
  (token + 1) / 2 so that the loads (two tokens per quarter-warp phase)
  and the packed 4-byte FP8 stores (eight tokens per warp) are
  conflict-free. The values stay in registers between amax and quantize.
- The per-token amax is the per-thread running max over its 16 values
  followed by two XOR shuffles in the quad. cute::max(a, b) = a < b ? b : a
  never lets a NaN in and all inputs are non-negative, so the reduced amax
  is the same float as the serial 64-value max.
- The scale, clamp and reciprocal still go through
  sm90_fp8_mega_moe_get_e4m3_sf_and_sf_inv, each value is multiplied by the
  same sf_inv and converted with the same __nv_fp8x2_e4m3 pair constructor;
  two pairs are packed into one 32-bit store in the same byte order. The
  same SF rows (SF_BLOCK_M stride) and the same FP8 bytes (tokens below
  valid_m only, unswizzled [token][64] for the TMA store) are written, so
  the output must stay bit-identical to the image run 39053820377.
- Barriers, TMA store and arrival are unchanged; no extra CTA barrier, no
  register-budget change (komoriyuta's warp-redux-r176, one warp per token
  with a five-level shuffle and 176 registers, was slower in serving; this
  keeps 168 registers and does all 64 tokens in a single pass).
