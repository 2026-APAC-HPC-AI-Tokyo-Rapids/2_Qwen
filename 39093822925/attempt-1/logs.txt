Root cause of the gate failure in decode-sched / decode-all of the first job:
the host picks the geometry per rank from that rank's own token count
(SwapAB only for num_tokens <= 128), so one EP collective can mix the SwapAB
kernel on some ranks with the non-swap kernel on others. The gate's first case
cross-rank-empty-tail [7, 0, 65, 129] does exactly that (rank 3, 129 tokens,
non-swap). The flat barriers and the skipped pre-pull barrier changed the
cross-rank protocol of the SwapAB kernel only, so rank 3 waited in an NVLink
barrier whose signals never came and hit the 300 s timeout trap
(unspecified launch failure on rank 3 after ~5 min). Serving mixes geometries
too (94 SwapAB calls in a Prefill instance of run 39070273796). Those two
changes are dropped; every change here is rank-local.

- komoriyuta: control, as in the first job. (01) drop the unused remote L1
  top-k-weight read in the dispatch (Decode and Prefill branch; Prefill
  outputs stayed bit-identical in the first job) and (02) komoriyuta's
  parallel combine rebased onto the 8-patch chain. It matched my own combine
  (Decode-128 0.1994 vs 0.2002 ms) and is the simpler base.

  loader claims the next block from a rank-local counter (spare L2

  4-slot shared-memory ring; same index space and decoding as the static

  combine buffers move past the expert-count region so they never overlap

- sched: 01 + dynamic assignment without the combine change.
