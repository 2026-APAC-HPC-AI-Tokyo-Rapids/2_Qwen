with extra="forbid", so only the key max_tokens populates the field and
the OpenAI name max_completion_tokens is rejected. My earlier reading of

the same value (200) for the official command.

ChatCompletionRequest pops max_completion_tokens and uses it only when
max_tokens is absent. Generation parameters are unchanged (max_tokens 200
either way). A minimal pydantic 2.14 model with the same field and config
reproduces the rejection and accepts the patched body, including the
field-name dump the gateway forwards to workers.
