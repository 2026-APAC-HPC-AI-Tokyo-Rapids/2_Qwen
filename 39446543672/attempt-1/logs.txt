2026-10-20T15:14:24.9907612Z   QWEN_COMMIT_MESSAGE: [cluster:firmus] [nodes:1] [kernel-bench] Benchmark flat NVLink barriers for Prefill workers

Why

Prefill is the current serving bottleneck. The earlier all-geometry flat
barrier experiment reduced Prefill MegaMoE time by about 1.2% but regressed
Decode by about 3.3%. Re-test that synchronization change on the current
SF128 plus FC2-swizzle header while keeping arithmetic and geometry fixed.
These earlier measurements are motivation, not results of this revision.

A geometry-conditional protocol is unsafe: one Prefill instance can run
Prefill, SwapAB Decode and non-SwapAB geometries in the same EP collective,
including an idle rank. All ranks must send and wait for the same signals.
The candidate therefore changes the protocol for every geometry. Its serving
scope is the Prefill worker instance, not a template geometry condition.
The parent session will separately arrange worker-specific overlay mounts;
this change does not edit provisioning, scheduler scripts or serving config.

What

Rebase the af144db all-geometry flat NVLink barrier onto image 39126563684
followed by the existing SF128 and FC2-swizzle overlays. Replace the pre-pull
NVLink barrier with release.sys count publication and a system acquire plus
async-proxy fence after the existing count wait. Replace pre-combine and
cleanup barriers with monotonically increasing u64 counters in the last two
unused L2 arrival-mask slots. Every CTA signals every rank; at EP4 with 132
CTAs each counter advances by 528 per call. Derive each wait target from the
local atomic return value. All math CTAs wait before combine; only dispatch
SM0 waits for final cleanup. Preserve the dispatch/math handshake, existing
claim resets and the generic-to-async proxy fence before combine TMA reads.
No workspace size, arithmetic, quantization, routing or output type changes.

Stage control-sf128-swizzle and prefill-flat-barrier with numerical gate,
bench and timeline for each, plus the image bench: seven total steps. The
candidate directory name describes the intended worker deployment; the
header protocol covers all geometries. Also place the same third patch in
deep-gemm-overlay as sm90-prefill-worker-flat-nvlink-barriers.patch without
enabling it in config.

Use the control timeline from 7d7e5d3 and rebase its instrumentation onto the
candidate. Preserve all 30 counters. Removed pre-pull and grid-sync events
remain unset rather than adding synchronization solely for timing. Read the
candidate's total pre-combine interval from MLoopExit to MCombineBarrier and
its final interval from DispClean to DispExit. The corresponding old split
phase rows show missing values. Update only COUNTERS and CYCLE_COUNTERS in
the summary script to the two lines from 7d7e5d3.

Checks

CPU-only compilation on the Firmus login node using the pinned image's
CUDA 13.0.88 succeeded for control and candidate, normal and timeline, in all
three requested geometries: twelve compilations. Normal Prefill uses 96
registers, 24-byte stack and 20/20-byte spill stores/loads in both versions.
Normal decode32 and nonswap both use 168 registers, 8-byte stack and zero
spills in both versions. Timeline Prefill is 96 registers, 40-byte stack and
56/60-byte spills in both; timeline decode32 is 168 registers, 24-byte stack
and 28/136 bytes for control versus 28/120 for candidate; timeline nonswap
is 168 registers, 8-byte stack and zero spills in both. No register or spill
regression against the corresponding control was observed.

Control normal SASS hashes match the known values: Prefill 080b4898bf885932,
decode32 5bcd675b848f5341, nonswap 14be1261f0978108. Candidate normal hashes
are c0901bf33b41ae8b, 5bdd44dee2462157 and 4caf31d93358078d respectively.
The candidate header SHA-256 is
c26bb31b1e0c4cdfa5999489860912072878e42b109dce42a8c553c20c543e63.

Each image-to-overlay application and each candidate-specific timeline
passed git apply --check. Applied headers match the CPU-compiled inputs
byte-for-byte. Bench and serving overlay third patches are identical.
The control patch files match 7d7e5d3, all 30 counter names/order match the
timeline helper, and every other summary-script line remains at main.
All 22 tests in test_firmus_kernel_bench.py passed. To honor the no-commit
constraint, only the test fixture's patch-generation helper was replaced at
runtime with an equivalent unified-diff writer; all test assertions ran.
The test's scheduler command is a recording-only stub, not a GPU job.
Commit-message tag validation and whitespace checks passed. The dedicated
Firmus work directory was made user-writable and deleted, with absence
verified. No GPU jobs, commits, pushes or branches were created by this task.

Expected

Measure whether the prior small Prefill gain survives the current SF128 and
swizzle baseline. Compare uninstrumented Prefill timings and use the timeline
to explain synchronization costs, not as the serving-performance score.
Decode-case timing is informational: this header is not intended for Decode
workers, whose existing header remains the deployment baseline. All geometry
cases still participate in the candidate's numerical correctness gate.

Risks

GPU numerical gates, mixed/idle behavior, repeated CUDA graph replay and
serving goodput are not yet measured for this revision. Static barrier
reasoning assumes identical candidate headers and capacities on every rank,
132 CTAs per rank, the same collective order, stream-ordered reuse of one
workspace, collective zero initialization and no u64 counter wrap. Atomic
contention can erase the expected gain. CPU compilation and spill counts do
not demonstrate a runtime speedup or GPU hang freedom. Keep control and
candidate protocols out of the same EP collective.

The optional readiness-tag candidate was not implemented because uniqueness
of gridid generations across CUDA graph replay was not established here.
Do not infer its safety from the SM100 reference alone. Worker-specific
mounting remains a separate integration task before any serving adoption.
