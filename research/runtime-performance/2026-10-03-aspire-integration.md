# Local ASPIRE integration preparation

This branch ports the audited P-only CUTLASS candidate `ac3c70d` onto main `5c2ccd5`. It is preparation, not adoption or a performance result. Candidate Actions run `37093476615`, attempt 1, scored 2570.325310255 output tokens/s versus control 2472.821915302 (+3.943001%). A single comparison does not establish repeatable benefit. The repository result parser implements the published task rules; it is not organizer-supplied. Matched repeats remain the performance gate.

The eight runtime files are `configs/aspire-serving.json`, `.github/workflows/aspire2ap.yml`, both ASPIRE PBS/checker files, `scripts/stage-qwen-node-model.sh`, the standalone `research/simulation/{prepare_eagle,greedy_probe}.py` helpers, and the shared `submission/run/submit.sbatch`. The shared runtime scopes ASPIRE concurrency, topology, FP8 KV, prefill CUTLASS, EAGLE3, explicit worker environment, staging, readiness diagnostics, routing and post-benchmark evidence. Firmus/Genkai worker flags, topology, profile wrappers and startup defaults remain intact. NGRAM and draft quantization paths are omitted. The staging-helper install is confined to the ASPIRE workflow, leaving global provisioning unchanged. No runtime script is duplicated.

The candidate serving condition is two fixed nodes (`a2ap-dgx026`, `a2ap-dgx030`), 16 GPUs, P2TP4/D2TP4 EP1, concurrency 40, pool 131072 per worker, default chunk 8192, round-robin prefill routing, FP8 E4M3 KV, and EAGLE3 on both roles (steps 3, top-k 1, draft tokens 4). Prefill explicitly uses CUTLASS; decode keeps the automatic backend. The Nebius draft revision is `ff0f0c0999f6c86b21dfd2f5803eebc4ac712224`. Its original BF16 weights and integer maps remain unchanged; preparation changes only the native EAGLE3 architecture selector and explicit dtype, recording original/runtime config and weight provenance.

The executable fixture `qwen-experiment-metrics/tests/test_aspire_integration.py` runs the actual Bash worker function and topology with recording Enroot stubs. Its checked-in expected commands come from candidate `ac3c70d` for ASPIRE and main `5c2ccd5` for other platforms. The fixture also records source commits and SHA256 hashes of the four audited server-info artifacts. It checks all four candidate workers, archived explicit server flags, router commands, and the complete archived AIPerf argument array. Other-platform checks include both Genkai node counts and profile wrappers. Local helper fixtures cover visible model copying without the hidden download cache, original BF16 draft preservation, rejection of wrong draft precision, greedy request/logprob evidence, PBS terminal outcomes and result-parser failure propagation. Enroot, PBS, GPU and benchmark services are stubbed; these checks allocate no GPUs.

Reproduce the inexpensive checks from this branch:

```bash
find scripts platforms containers aws submission -type f \( -name '*.sh' -o -name '*.pjm' -o -name '*.pbs' -o -name '*.slurm' -o -name '*.sbatch' \) -print0 | xargs -0 -r -n1 bash -n
uvx --from pyyaml python -c 'import pathlib, yaml; [yaml.safe_load(path.read_text()) for path in pathlib.Path(".github/workflows").glob("*.yml")]; [yaml.load(path.read_text(), Loader=yaml.BaseLoader) for path in pathlib.Path("aws").glob("*.yml")]'
uvx --from 'actionlint-py==1.7.12.24' actionlint
uvx --from 'cfn-lint>=1.38,<2' cfn-lint aws/qwen-build-infrastructure.yml
uv run --project qwen-experiment-metrics ruff check qwen-experiment-metrics scripts research/simulation/prepare_eagle.py research/simulation/greedy_probe.py
uv run --project qwen-experiment-metrics pytest -o addopts='' -q qwen-experiment-metrics/tests
```
