# Qwen3 PD Basic submission — Firmus, Tokyo Rapids

**Classification: Basic.** This is the submission the organisers re-run. It serves the official FP8 checkpoint with the unmodified public SGLang **0.5.23** release (upstream commit `297e54fd105e974cdf401e5b4d20253a22c16f90`) on Firmus, 2 nodes / 16 H200. Only built-in options, environment variables and deployment settings are tuned. SGLang, its kernels, DeepGEMM and the gateway are not patched, and no runtime overlay is applied. The team's source and kernel work is the separate [Bonus package](../README.md).

## Selected runtime

- **Topology**: three Prefill workers and one Decode worker (P3/D1), four GPUs each. Public flags `--tp-size 4 --attn-dp-size 4 --ep-size 4`, that is attention TP1/DP4 and MoE EP4.
- **Kernels and memory**: FA3 attention, FP8 E4M3 KV cache, page size 64, the release's own MegaMoE with the DeepGEMM runner, memory fraction 0.90.
- **Routing**: both roles use `--load-balance-method total_requests --load-snapshot-publish-interval 1`.
- **Prefill**: chunked prefill 16384 globally (4096 per DP rank), `--prefill-max-requests` not set, KV pool 32768 tokens per rank, global request cap 256. No CUDA graph.
- **Decode**: KV pool 393216 tokens per rank, global request cap 128 (32 per rank), CUDA graph batch sizes 1, 2, 3, 4, 6, 8, 12, 16, 20, 24, 28 and 32.
- **Speculative decoding**: EAGLE3 with steps 3, draft tokens 4, top-k 1. The target verifies every token.

The complete public argv and environment are generated by [worker.py](worker.py) from [configs/firmus-basic.json](../../configs/firmus-basic.json), which is byte-identical to the configuration both measured runs used; each measured worker's record is in `results/<run>/launch/`. The job scripts were rewritten afterwards, for readability and down to the steps of a successful run: input checks, traps, timeouts, the in-job server-info validator and the diagnostic EAGLE acceptance collector were removed, and `worker.py` replaces the launcher those runs used (`scripts/basic-worker.py`). `worker.py` produces exactly the argv and environment of every worker record in `results/<run>/launch/`. `test_scripts_do_what_the_measured_scripts_did` in `qwen-experiment-metrics/tests/test_submission_package.py` runs `prepare.sh` and `submit.sbatch` with every cluster command stubbed and requires the same srun steps and argv, the same ordered HTTP calls (less the removed validator and collector) and the same run-directory files as the scripts those runs used.

## Draft declaration

The sole draft is public [nebius/EAGLE3-Qwen3-235B-A22B-Instruct-2507](https://huggingface.co/nebius/EAGLE3-Qwen3-235B-A22B-Instruct-2507), revision `ff0f0c0999f6c86b21dfd2f5803eebc4ac712224`: **572,538,880 parameters, BF16, 1,145,943,008 weight bytes** (CC-BY-4.0). Basic serves it in BF16, without load-time quantization. `submission/run/prepare_eagle.py` changes only the architecture selector and explicit dtype declaration in its config; weights are unchanged, and the downloaded weight SHA-256 recorded in `source/draft-provenance.json` is `bf226a966868fe413a22e62e471aa1130bd94f17fd2c40d322b1c8b4def1ae86`. No draft is trained or fine-tuned.

## Build

The image is the official `lmsysorg/sglang` v0.5.23 linux/amd64 image, pinned by digest `sha256:f7876bef696ccf9cf75a2bf7ccb82970f5fac577f082fb8ca95c9a59d2160eb5` in [containers/basic.Dockerfile](../../containers/basic.Dockerfile). The recipe adds AIPerf 0.12.0 and `sglang-router` 0.3.2 in a separate `/opt/aiperf` environment, so they never resolve or replace the inference packages, plus a provenance manifest and an image self-check. Serving uses the gateway binary shipped in the official image.

Build on a root Linux host with Buildah (`chroot` isolation), Skopeo, Umoci, SquashFS tools, Git and jq. From the repository root:

```bash
sudo env BUILD_DIR=/var/tmp/qwen-basic-build CONTAINER_ARCHIVE_DIR="$PWD/submission/basic/build/output" GITHUB_WORKSPACE="$PWD" GITHUB_SHA="$(git rev-parse HEAD)" GITHUB_RUN_ID=100001 GITHUB_RUN_ATTEMPT=1 scripts/build-basic-container.sh
```

`BUILD_CACHE_REPOSITORY` is optional (a writable OCI registry for Buildah layer caching). Outputs are `100001.sqsh` and `100001.container-sidecar.json`. The measured image is build **41046995676** from Qwen `aa48ceeca33afc27c2995713d55d4a4c65d02fc1`: **16417116160 bytes**, SHA-256 **d6ea5d95d6d76ab87ea55aeb70a052f04dbba8f9bbd515c3ece394690b2a1058**. `build/build.log` is that build's raw Buildah log and `build/provenance.json` its sidecar. Since that commit, `scripts/build-basic-container.sh` changed only to make the registry cache optional (`53a90cc`); the Dockerfile and image check are unchanged. Bit-for-bit reproducibility of a fresh archive has not been established.

A new build has a different artifact identity. Copy `configs/firmus-basic.json` and set `container_build_run_id`, `container_source_commit`, `container_sha256` and `container_size_bytes` from the new sidecar; keep the published pins unchanged to reproduce the existing measurement.

## Prepare and run

The whole repository is required: `prepare.sh` copies `worker.py`, `submit.sbatch` and the shared AIPerf and draft helpers of `submission/run/` into the run directory. On the Firmus login node, place the image with its sidecar (`BUILD.sqsh` and `BUILD.container-sidecar.json` side by side), the official target `Qwen/Qwen3-235B-A22B-Instruct-2507-FP8` revision `e156cb4efae43fbee1a1ab073f946a1377e6b969` (all 24 shards and metadata), and a tokenizer snapshot of `Qwen/Qwen3-235B-A22B-Instruct-2507` revision `ac9c66cc9b46af7306746a9250f23d47083d689e` (`config.json`, `generation_config.json`, `merges.txt`, `tokenizer.json`, `tokenizer_config.json`, `vocab.json`) on shared storage. Preparation downloads the pinned public draft and declares its SGLang architecture and dtype (`prepare_eagle.py`).

```bash
bash submission/basic/prepare.sh /scratch/home/ACCOUNT/qwen-basic-run /shared/BUILD.sqsh /shared/Qwen3-235B-A22B-Instruct-2507-FP8 /shared/tokenizer/ac9c66cc9b46af7306746a9250f23d47083d689e configs/firmus-basic.json
```

```bash
cd /scratch/home/ACCOUNT/qwen-basic-run
```

```bash
sbatch --export=PATH,HOME,USER,LOGNAME scripts/submit.sbatch
```

`prepare.sh` creates the run directory, links the image, writes the effective configuration with the image's pins, stages the tokenizer cache and the draft, and copies the job scripts. The single Slurm script (partition `hpcai`, two nodes, eight GPUs per node, 17 minutes) starts the P3/D1 workers and the public gateway, waits for readiness, records every worker's server info (release, layout and KV pools), sends one connection sanity chat, and then runs the unchanged official AIPerf command (60/120/30 seconds, seed 2026, closed-loop c160). AIPerf runs from the isolated `/opt/aiperf` environment. The partition and resource lines are for Firmus.

## Outputs

Check the job's terminal state and exit code, then `results/score.json`: `eligible`, the good request fraction and request errors. **Good output tok/s = `goodput.avg × 200`** from `results/profile_export_aiperf.json`. `run-success` marks a job that ran to the end; the server info is recorded again after the benchmark. The sanity chat and the local scorer do not replace the organisers' full-set accuracy check. Preserve `source/`, `logs/` and `results/` of the run directory before deleting it.
