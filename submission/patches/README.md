# Changes carried by the submitted stack

**143 rows; 30 are marked `to confirm`** (47 `bit-identical`, 24 `FP-order`, 42 `no numeric effect`).

Paths outside `submission/` refer to the accompanying repository, which is required for rebuilding the image. Runtime patches are text copies numbered in application order; their source paths remain canonical. No kernel or patch content was changed for this package; one runtime overlay (`34-pp4-direct-logprob.patch`) was added after the measured run. The image is build 41729881283 from Qwen `3f9124fd8afb28e34c71288b6dc31e5c490c7f60`; every build input listed here is byte-identical between that commit and the `main` commit this package is based on.

Source reconstruction starts from public [sgl-project/sglang](https://github.com/sgl-project/sglang) `0d6bef6b6d2f4fa03187fb4d02773ad6e1256adb` (shallow fetch). Its tree `9ea4c7300d38bd9e024330b45bf5fc9cbf70f97d` is identical to the team mirror’s rewritten-history boundary `6b3506869d4840b18678de19d18d751a34f9b737`, which does not exist upstream. `build/sglang-6b350686.commit` is the raw original commit object; `git hash-object -t commit -w` recreates it exactly, and it is marked shallow. The bundle then adds the three team commits, reconstructing `fc275674a97d78553b22597ee72c8fd48f5420f4` exactly without private repository access. The three extra commits remove upstream CI, lock `python/uv.lock`, and add/update a mirror workflow. DeepGEMM host sources are public `sgl-project/DeepGEMM` v0.1.5 (`1c8138a59b3df5dac50b76b730834ed57982fdfb`); its ordered JIT-header and host patch series are separate. Router sources are the pinned PyPI `sglang-router` 0.3.2 source distribution. FA3/CUTLASS source pins and compiler flags are in `kernels/fa3-verify/build.py`.

Classes: **bit-identical** means the same operations and order; **FP-order** means the same operations with changed floating-point summation or FMA order; **no numeric effect** means scheduling/runtime/build metadata. **to confirm** explicitly marks cases where the patch text and the recorded evidence do not establish one of those classes; the basis then says what is open. A class does not certify the organisers' full-set accuracy check. Optional companion candidates remain listed even when the pinned run does not select them.

The basis column states, from the patch text itself, what the change computes and why it is or is not the same math, with the measured evidence where one exists (evidence files are cited by their path inside `submission/`). It also says when a switch is not enabled in the served configuration (`config/prefill-kernels.env`, `config/decode-kernels.env`, `run/worker.sh`, `run/submit.sbatch`). A `bit-identical` row is relative to the control named in its basis (for example `prefill-v3.patch` is byte-equal to the P row, not to stock attention). The selected Prefill N192/M192-N96 pair and Decode split-attention paths are not claimed bit-identical to the stock attention geometry.

Image build order is the SGLang array in `scripts/build-sglang-container.sh`, then the DeepGEMM `series` files and the Dockerfile steps. Runtime order is each numbered overlay directory (34 SGLang, 14 DeepGEMM), exactly the `sglang_overlay_patches` and `deep_gemm_overlay_patches` lists of `configs/firmus-prefill-pp4.json`; the SHA-256 values of the first 33 SGLang and all 14 DeepGEMM overlays equal the `sglang-overlay.json` and `deep-gemm-overlay.json` records of run 41767886175, and the 34th was added after that run. The build-time compile check `containers/check-sm90-independent-wg.py` also applies the `deep_gemm_overlay_patches` list of `configs/firmus-framework.json`, including [patches/deep-gemm-bench/fc2-address/fc2-output-address.patch](../../patches/deep-gemm-bench/fc2-address/fc2-output-address.patch) (`e27a434498753b369ad17c7cc3b7c499edc2d5e5156f62fcd21b18cc2c8074cb`), to a temporary header copy only; that check does not change the installed package and the patch is not served.
